# Issue 69: pi-subagents integration research

Research date: 2026-09-25. Upstream inspected at [`2e9c51bada2da6a9ba73b6973e1545a9afa0d057`](https://github.com/nicobailon/pi-subagents/tree/2e9c51bada2da6a9ba73b6973e1545a9afa0d057), package version 0.71.0. This report describes that source, not every released or locally installed version. No implementation or upstream changes were made.

## Conclusion

Atelier can integrate existing structured foreground results and live async completion events today. Reliable attribution must distinguish **reported direct child usage with launch configuration** from **actual usage grouped by provider/model/effort**. Current upstream exposes the former well enough for ordinary fixed-configuration runs, but does not persist a complete versioned accounting contract across all paths. It also has a public `cost` RPC already: do not invent a duplicate API or import private upstream modules.

The smallest reliable cooperation is to preserve a bounded accounting projection across existing result, update, completion, replay, and metadata paths. For full issue acceptance, that projection must carry per-actual-provider/model/effort buckets, stable ownership/identity, and explicit scope. An Atelier-only adapter can support known data and report unavailable attribution; it cannot reconstruct metadata already discarded or artifacts already deleted.

## Public surfaces and compatibility

The documented event-bus RPC uses `subagents:rpc:v1:ready`, `subagents:rpc:v1:request`, and `subagents:rpc:v1:reply:<requestId>`. `ping` advertises `cost`, status/fleet capabilities and event names. The read-only `cost` response is `{ version: 1, parent, children, childTotal, total, unresolvedAsyncChildren }`; each child can have `agent`, `runId`, `sessionFile`, and usage. It does **not** return model, provider, effort or child index. It is intended for turn-boundary requests, not polling. The fleet DTO is explicitly bounded and its reconciliation keys are opaque, so it is not a durable accounting ledger. [RPC contract](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/docs/extension-api.md#L96-L156)

Current upstream declares `@earendil-works/pi-ai >=0.86.1` and develops against Pi 0.87.0. This is newer than the locally inspected Pi 0.84.0. Pin and manually exercise a supported host/producer pair before claiming compatibility; a package version alone is weaker evidence than runtime capabilities and validated payloads. No conclusion in this report proves current upstream can run on Pi 0.84.0. [Package manifest](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/package.json#L77-L117)

## Data actually emitted

| Path | Available evidence | Limits / integration consequence |
| --- | --- | --- |
| Foreground single, parallel, chain | `Details.runId`, stable `SingleResult.index`, agent, usage, model, thinking; streaming updates clone cumulative usage | Replace observations by stable identity; never add every update. Model/effort describe launch configuration, not guaranteed per-response attribution. |
| Foreground workflow | Flattened child results add `workflowKey`; root details carry root run ID and workflow receipt/child summary | Resolve the child's own run identity from workflow evidence. Root run plus numeric index alone is insufficient if independent child launches each start at index 0. |
| Slash foreground | Custom message `details` wraps `{ requestId, result }`; initial and final snapshots share correlation | Parse the known wrapper; collapse snapshots. Custom-message usage is not native tool-result usage. |
| Async launch | Result has `runId`, `asyncId`, `asyncDir`, empty `results` | Dispatch is evidence of pending work, not a zero-cost completed child. |
| Async runner completion | Result file writes per-child usage/model/thinking/sessionFile; full payload reaches `subagent:async-complete` | Live attribution is feasible now. Validate owning session and normalize run/step identity before persisting locally. |
| `bg_wait` | `details.completions[]` gives root run and child run ID where producer supplies it, usage, sessionFile, model | Projection drops thinking and stable index. It does not recover all metadata present in the original completion. |
| Async notification | `subagent-notify` custom message contains text/display only | No structured usage or details are persisted here. Do not parse notification prose into accounting facts. |
| Metadata / completion replay | Metadata can retain usage/model; replay retains projected completion with expiry | Metadata omits effort and replay drops it; files are optional or retention-managed. Historical complete reconstruction is not guaranteed. |

Foreground initialization actually assigns index/model/thinking/usage, rather than merely declaring them in types. Streaming snapshots copy cumulative usage and drop messages; completed compaction also removes messages. The documented stable identity guarantee applies to foreground results and says to use `(runId, index)` rather than row position. [Initialization](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L460-L475), [stream snapshots](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L248-L275), [completed compaction](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/shared/utils.ts#L392-L410), [identity contract](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/docs/extension-api.md#L143-L144)

Workflow flattening preserves child rows and adds `workflowKey`; root output uses its own run ID. The adapter must interpret workflow ownership rather than assuming the flat array has globally unique indices. [Flattening](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/subagent-executor.ts#L4574-L4575), [workflow output](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/subagent-executor.ts#L6327-L6347)

Slash execution persists both initial and final structured snapshots, using `requestId` and wrapped `result`. [Slash messages](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/slash/slash-commands.ts#L537-L565), [wrapper](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/slash/slash-live-state.ts#L9-L12)

## Usage scope and double-count hazards

1. **Direct child usage excludes descendants and compaction.** The foreground listener adds usage only for assistant messages. Final reconciliation also scans assistant messages only, from a recorded baseline. Background execution uses the same reconciliation. Therefore adding parent `toolResult.usage` from nested subagent calls or compaction entries is not part of the reported direct `result.usage`. A descendant-inclusive cost aggregate is a different scope. [Live accounting](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L1066-L1104), [reconciliation](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/shared/usage-reconciliation.ts#L44-L74), [background accounting](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/background/run-child-session.ts#L511-L530)
2. **Native tool usage and detailed rows represent the same direct spend.** `withAggregatedToolUsage` writes the sum of direct result usage onto returned tool `.usage`; conversion includes input/output/cache-read/cache-write in total tokens. Counting both native usage and rows doubles foreground spend. `details.totalCost`, however, recursively adds nested costs, while `sumResultsUsage` does not. Neither is an extra additive source. [Native aggregate](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/subagent-executor.ts#L3073-L3087), [direct and nested sums](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/shared/utils.ts#L343-L389)
3. **Launch model is not actual response model.** Result starts with the launch model. Later assistant `message.model` updates progress but only sets result.model if absent. A child extension can change model/effort, and completed messages can be removed, leaving no per-response grouping. Requested model is distinct from resolved model. Never relabel the whole run using the final response or current parent configuration. [Model observation](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L1097-L1103), [selection evidence](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/shared/model-resolution.ts#L399-L420)
4. **A child session can be reused.** Attempts reconcile only messages after `messageBaseline`; recovery sums attempts into aggregate usage. Reading the entire child session can count forked inherited history and earlier resumed runs again. Session path is evidence location, not unique execution identity. Per-run usage needs a boundary or producer bucket. [Baseline](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L1400-L1415), [attempt sum](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L1855-L1877), [final aggregate](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L1904-L1924)
5. **Success is not a cost filter.** Terminal payloads include failed/stopped/timed-out results with whatever usage was observed. Preserve those costs; keep failed metadata persistence distinct from failed execution. [Terminal serialization](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/background/subagent-runner.ts#L4938-L4979)

## Why cost RPC v1 cannot be the accounting authority

The implementation traverses `getBranch()`, not all session entries; parent usage is assistant plus compaction only. It ingests foreground tool results, `bg_wait`, and recognized slash wrappers. Child identity prefers child `runId`, then sessionFile; it does not use parent Details.runId plus SingleResult.index. This can collapse repeated runs on one session path and cannot deduplicate identityless records. These are code-path risks, not a claim that every normal run miscounts. [Collector](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/slash/subagent-cost.ts#L111-L121), [dedupe and branch scope](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/slash/subagent-cost.ts#L163-L197)

Async recovery in this collector follows **workflow** run IDs into receipts and per-run metadata. Standalone async launch receipts have empty results and are not workflow roots; text-only native notifications are not parsed. Missing child metadata increments `unresolvedAsyncChildren`, but missing/unreadable receipt errors are caught without incrementing it. Zero unresolved is therefore not proof of complete coverage. The documentation explicitly calls this lower-bound limitation out. [Workflow recovery](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/slash/subagent-cost.ts#L212-L250), [documented limitation](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/docs/observability.md#L30-L34)

Use this RPC for optional diagnostics or scope-aware enrichment. Never add its `total` to native Pi totals, and do not compare all-session Atelier totals with current-branch RPC totals as an invariant.

## Lifecycle, restart and ownership

`subagent:child-status` is a versioned lifecycle hint with runId, childId, status, timestamp and optional step/agent/childRunId/workflowKey. It is not a usage stream. Hints may duplicate and are not replayed after restart; snapshots are authoritative for status. In-process events do not reach detached processes directly. [Contract](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/docs/observability.md#L209-L224), [process boundary](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/docs/observability.md#L307-L323)

The watcher validates sessionId, completion owner, and an epoch to prevent stale callbacks delivering into a replaced session. Completion owner is process-stable across extension reloads. It writes replay before notification/deduplication/cleanup, then emits the observer event, and removes the one-shot result after persistence succeeds. An observer exception is caught; it is not an acknowledgment protocol guaranteeing Atelier saved the event. [Owner identity](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/shared/completion-owner.ts#L1-L14), [session guard](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/background/result-watcher.ts#L223-L238), [replay ordering](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/background/result-watcher.ts#L411-L439), [event/cleanup](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/background/result-watcher.ts#L587-L620)

Durable replay records carry owner session, root run, expiry and projected WaitCompletion, not the full original payload. Foreground and background metadata writers omit thinking, stable index and sessionFile despite richer live result objects. Artifact availability must remain optional evidence, never assumed permanent. [Replay serialization](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/background/completion-replay.ts#L185-L208), [foreground metadata](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/foreground/execution.ts#L137-L174), [background metadata](https://github.com/nicobailon/pi-subagents/blob/2e9c51bada2da6a9ba73b6973e1545a9afa0d057/src/runs/background/subagent-runner.ts#L1491-L1510)

## Recommended implementation boundary

These are recommendations inferred from the source, not existing upstream guarantees.

- Keep one optional pi-subagents adapter behind the Atelier ledger. Validate known structured shapes, version/capability-gate optional RPC, and tolerate absence. Do not require a runtime Node import of an independently installed extension.
- Normalize observations into owner session, stable root/child execution identity, source revision or cumulative snapshot, direct usage, configuration evidence, terminality and coverage. Upsert; do not sum snapshots. Store source links to native tool-result entries so exact mirrored spend replaces attribution without adding cost again.
- Support foreground normal runs, workflow mapping, slash wrapped results, bg_wait completions and live async completion separately. If stable identity or configuration is missing, retain known total as unknown attribution rather than guessing. Aggregate launch-attributed usage may be shown only with that limitation explicit.
- Persist accepted async accounting in Atelier-owned session entries while the owner session is active. Reload them idempotently. Guard queued work by session ID/generation and unsubscribe on disposal. Do not steal ownership, delete upstream files or deliver upstream notifications.
- Prefer explicit producer pointers and targeted reads, bounded by size/count. Avoid scanning all global child sessions. Import child JSONL only when producer evidence supplies ownership and per-run boundaries; otherwise a whole-file sum is unsafe with fork/reuse.
- Treat live status as a hint to refresh known snapshots. Current `child-status` alone cannot supply exact live token/cost updates. Never use a busy polling loop around the synchronous cost collector.

### Minimal upstream cooperation for full reliability

Extend existing structured payloads instead of adding another RPC:

1. Preserve one bounded, versioned accounting object in foreground final/update details, async terminal event/result, persisted notification details, wait completion and replay. Include owning parent session, root and child run identities, stable step/workflow key, and explicit direct-versus-inclusive scope. Notification persistence closes the demonstrated loss after result cleanup/retention, including sessions where Atelier was not loaded at completion time.
2. Include actual provider/model/effective-effort usage buckets captured at each request boundary. Do not only copy the resolved launch model. Retain unknown effort/provider explicitly when unavailable. Include compaction/summary or other model-call buckets if total scope promises all spend; define nested children as separate identities and declare whether native aggregate usage includes them.
3. Preserve monotonic revision/finality or another deterministic snapshot ordering rule, and indicate missing/incomplete coverage. Define whether updates replace prior cumulative snapshots, and give resumed executions distinct accounting identities even when they reuse one child session.
4. Keep native tool `.usage` synchronized with the same documented aggregate scope, so Atelier can reconcile a single native contribution with its attribution. Do not add async usage to a previously accounted foreground contribution again when a detach is reconciled.

Until this is implemented and validated, full actual model/effort, historical async and recursive attribution cannot be declared complete. A phased adapter is still useful if the UI reports these limitations and existing total behavior stays explicit.

## Verification evidence to collect during implementation

Use source-derived non-TUI fixtures or an adapter harness for identity, arithmetic and persistence; follow repository policy by writing no TUI unit or end-to-end tests. Manual TUI TODOs should cover: same-named parallel children; mixed chain/parallel indices; workflow independent index-0 children; mid-run model/effort change; reused/forked child sessions; direct and nested costs; async single and workflow completion; duplicate wait/event observations; detach/resume; abort with nonzero spend; missing metadata/expired replay; reload; session switch while a completion arrives; Pi/producer version mismatch; producer absent.

The integrated plan must provide an isolated temporary Pi launch loading only the updated Atelier plus the pinned pi-subagents extension for this compatibility pass, with auto-loaded duplicate extensions disabled. The exact command depends on the selected compatible host version and should be verified against that host's CLI before delivery.
